# Quartz网站优化路线图

这是一份给当前个人站点用的优化清单。目标不是一次性重构，而是按优先级一步一步推进，先把发布正确性和站点基础打稳，再做内容和体验上的整理。

## 放在哪里合适

这份记录放在 `技术总结/个人网站搭建计划` 下面最合适，因为它直接服务于站点建设、发布和维护，不属于泛技术总结，也不属于日常计划。

推荐关联的内容页：

- [[利用quartz开源项目搭建个人博客]]
- [[电脑端更新维护说明]]
- [[手机端更新维护说明]]

## 优化目标

1. 让自定义域名发布稳定生效。
2. 让站点链接、RSS、站点地图、页面标题统一正确。
3. 让首页和分类页更清晰，方便后续持续写内容。
4. 让部署流程简单、可重复、少出错。

## 第一阶段：先修基础配置

- `quartz.config.ts`
  - [x] 把 `baseUrl` 改成自定义域名对应的正式地址。
  - [x] 把 `locale` 改成 `zh-CN`。
  - 保留 `cname`，确保构建产物里能生成 `CNAME`。
- `.github/workflows/deploy.yml`
  - [x] 把 `npm install` 改成 `npm ci`。
  - 检查是否还需要保留 `keep_files: true`，通常更建议干净发布。
- `quartz.layout.ts`
  - [x] 把页脚链接换成站内导航入口。

## 第二阶段：整理内容结构

- 首页 `content/index.md`
  - [x] 改成清晰的总入口。
  - [x] 明确列出四个主分类。
  - [x] 增加推荐阅读路径。
- 分类入口页
  - [x] `content/佛法/完整的世界观.md`
  - [x] `content/人生感悟/这是我的感悟.md`
  - [x] `content/技术总结/技术总结.md`
  - [x] `content/我的计划/宏大的计划.md`
  - [x] 统一做成分类目录页，而不是普通文章。
- frontmatter
  - [x] `content/index.md`
  - [x] `content/技术总结/情报与资源收集.md`
  - [x] `content/技术总结/AI开发审计追踪.md`
  - [x] `content/技术总结/因果推算.md`
  - [x] `content/技术总结/claude使用.md`
  - [x] `content/技术总结/从形式走流程过度到计划开启.md`
  - 统一 `title`、`description`、`tags`、`status`、`date` 的写法。
  - 状态字段尽量固定为少数几个值，后面更容易筛选。

## 第三阶段：改善发布体验

- 图片和附件
  - 把零散图片统一归档到固定位置。
  - 避免根目录越来越乱。
- 构建和预览
  - 增加一个本地预览命令。
  - 保留发布前检查命令。
- 性能
  - 视情况关闭较重的构建功能，例如自定义 OG 图片。
  - 后续再看要不要改成本地字体方案。

## 当前执行顺序

1. 先改 `baseUrl`、`locale`、`deploy.yml`、页脚链接。
2. 再整理首页和四个分类入口页。
3. 接着统一 frontmatter。
4. 最后再处理图片归档和构建体验。

## 备注

你已经确认网站内容本身就是公开展示用途，所以不必单独做隐私隔离，这条可以不作为当前优化项。
