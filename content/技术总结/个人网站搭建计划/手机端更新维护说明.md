# 手机端更新维护说明

> [!success] 一句话
> 手机端只剩一件事：**写**。存进坚果云就结束了，同步、构建、发布、告警全在服务器上自动完成。

## 你不需要做的

- ❌ 装 Termux、`git pull` / `git push`
- ❌ 配 SSH 密钥、`ssh -T git@github.com`
- ❌ 手动构建、手动发布
- ❌ 担心「另一端是不是落后了」

这些都是 2026 年上半年的老流程，已经整体废弃。手机上开终端维护笔记，摩擦比写作本身还大，收益为零。

## 写完会发生什么

```text
你在 Obsidian 里保存
   │ 坚果云客户端自动上传（秒级）
   ▼
坚果云 WebDAV（唯一内容源）
   │ 服务器 systemd timer 每 5 分钟 rclone bisync
   ▼
/srv/nutstore → content/ → git push main
   │ Quartz 构建（约 30–40 秒）
   ▼
gh-pages 分支 → GitHub Pages 发布
   ▼
https://longbatian.site 已更新
```

时间预期：**保存后一般 1–3 分钟上线，最坏 5 分钟多一点**（取决于你正好卡在定时器周期的哪一段）。

需要立刻看到效果（比如改错字很急）时，也只能等这一轮同步，手机上无法手动触发——这是「只写作」的代价，换来的是永远不会忘记 push。

## 写作规范（重要，影响 URL 和链接）

### 1. frontmatter 用这套字段

```yaml
---
title: 文章标题
description: 一句话摘要，会用在站点预览和搜索
date: 2026-11-23
tags:
  - 技术总结
  - 某主题
status: published
---
```

- `title` 决定页面标题；`description` 决定搜索卡片摘要。
- `tags` 会进站点的标签体系，尽量复用已有标签，别每次造新词。
- `status` 固定用少数几个值（如 `published` / `draft` / `active`），方便以后筛选。

### 2. 文件名就是 URL

`技术总结/个人网站搭建计划/手机端更新维护说明.md` → `longbatian.site/技术总结/个人网站搭建计划/手机端更新维护说明`

- 文件名里**不要出现 `:` `/` `#` `?` 等字符**，中文和空格可以，但空格会被编码成 `%20`，所以能用短横线就用短横线。
- **定了就别随便改名**：改名后旧链接、外部收藏、别人引用都会 404。

### 3. 内部链接优先用 wikilink

```markdown
[[电脑端更新维护说明]]
[[技术总结/技术总结|技术总结分类]]
```

不要手写 `longbatian.site/...` 的绝对链接做站内跳转，换域名或改结构时会全崩。

## 手机上的图片怎么办

图床只能**在电脑端**上传（脚本或让 AI 上传），所以手机端按这个顺序处理：

1. **能不配图就不配图** —— 手机上文字优先。
2. **先占位，回电脑补图**：在需要图的位置写

   ```markdown
   ![](待补图-第3节-干支对应表)
   ```

   或者直接留一行 `> TODO 补图：干支对应表`，回电脑上传 R2 后再换成直链。
3. **图已经在图床上**：直接手打绝对链接，手机端可以完成：

   ```markdown
   ![](https://img.longbatian.site/btwy/xxx.png)
   ```

4. **千万不要在手机上插入本地图片附件**：它会被坚果云同步、被镜像进 `content/`、最终随站点发布，仓库和构建都会变重，而且和图床策略打架。真的临时插了，回电脑记得上传 R2 并删掉本地副本。

## 手机上可以让插件里的 AI 干什么

坚果云同步插件内置了 AI 对话框（就是现在这个），它在手机上能直接**读、改、新建**仓库里的 Markdown 文件，非常适合手机这种「打字难受」的场景：

| 场景 | 怎么下指令（示意） |
|---|---|
| 补 frontmatter | 「给 `技术总结/xxx.md` 按本文件夹模板补 title/description/date/tags/status」 |
| 改写成正式文章 | 「把 `D-日常项目跟踪总结/xxx.md` 里的碎片整理成一篇结构完整的文章，保留我的口吻」 |
| 批量改标签 | 「全库查找标签 `技术`，统一改成 `技术总结`，先列出会改哪些文件」 |
| 拆分长文 | 「这篇 8000 字的笔记拆成三篇，各自补 frontmatter，并建一个索引页」 |
| 查死链 | 「检查 `技术总结` 下的 wikilink 有没有指向不存在文件的」 |
| 生成本地分类页 | 「按 `index.md` 的 portal-card 写法，给我这个新文件夹做一个分类入口页」 |
| 排版校对 | 「只改错别字和标点，不要改我的措辞和句式」 |

使用注意：

- 默认**每次改动都要你批准**；也可以对某类操作放行，或在设置里开自动批准（YOLO 模式）。批量改文件前建议让它先列清单。
- 它可以连贯做多步任务（读文件 → 改文件 → 再检查），对话过程本身就是文件，会随同步跨设备，回家在电脑上能接着聊。
- 它的写入就是普通文件写入，保存后走同一条自动发布链路，所以**让 AI 改完就等于已经发布**，先让它给你看 diff。
- AI 在手机上**不能**上传 R2 图床，图片仍然要回电脑。

## 常见问题

### 改错了怎么回滚？

三层保险，从快到慢：

1. **Obsidian 自己的文件恢复**（核心插件「文件恢复」快照）。
2. **坚果云历史版本**：网页端对单个文件能看到历史版本。
3. **git 历史**：服务器和 GitHub 上都有每次同步的提交记录，可以回退某个文件。

### 删除笔记，线上会消失吗？

会。删掉坚果云里的文件 → 同步后 `content/` 里的文件被 `rsync --delete` 删除 → git 记录删除 → 重新构建后线上页面消失。**这是设计行为，不是 bug。**

### 为什么首页没有自动出现我的新文章？

首页 `index.md` 是手工策展的门户，「最近更新」也是手写列表。新文章会自动生成独立页面，并进入搜索索引、文件树、sitemap，但不会自动插进首页正文。

想让首页自动展示最近文章，需要在 Quartz 布局里加「最近发布」组件，见 [[Quartz网站优化路线图]]。

### 一次改了很多篇，会不会构建很多次？

- 同一个 5 分钟窗口内的所有改动会合并成**一次**同步、**一次**构建。
- 跨窗口的改动各构建一次，单次约 30–40 秒，有锁防止重叠，不会弄坏站点。
- 所以批量编辑时最好的节奏是：**攒着改完，再等一轮**。

### 手机上能看到构建是否成功吗？

插件 AI 看不到服务器日志，但可以间接验证：打开线上页面看是否已经是新内容。如果 10 分钟后仍是旧内容，说明这一轮同步或构建失败了，服务器会发邮件告警，回家再查。

## 检查清单

- [ ] frontmatter 五个字段齐全（title / description / date / tags / status）
- [ ] 文件名没有特殊字符，且不是临时名字
- [ ] 站内链接用 wikilink
- [ ] 需要配图的地方写了占位或 TODO
- [ ] 没有插入本地图片附件
- [ ] 没有在手机上跑 git 命令
