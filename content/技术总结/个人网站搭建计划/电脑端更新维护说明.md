# 电脑端更新维护说明

> [!info] 一句话
> 电脑端只做手机做不了的两件事：**精修长文** 和 **把图片传上 R2 图床**。同步与发布仍然全自动。

## 工作目录变了

| | 老流程（已废弃） | 现在 |
|---|---|---|
| 写作目录 | `E:\xiangmu\ShowMe\quartz\content` | 坚果云同步的 Obsidian 库（和手机同一份） |
| 同步方式 | CMD 脚本 `git checkout origin/main -- content/`、`git add content/`、`git push` | 坚果云客户端自动同步 |
| 发布方式 | 推 main 后等服务器拉取构建 | 服务器检测到坚果云变化后自动构建并推 `gh-pages` |

**不要再在 `quartz` 项目里写笔记。** 项目里的 `content/` 只是构建镜像，服务器每次同步都会用 `rsync --delete` 覆盖它，本地写进去的东西迟早消失。

**也不要再执行老的两段 CMD 脚本。** 现在手动往 `main` 推 `content`，下一轮镜像会把它覆盖；运气不好还会和服务器推送撞成 rebase 冲突，触发告警邮件。

## 日常流程

### A. 写 / 改文章

1. 打开 Obsidian（库 = 坚果云同步目录）。
2. 正常编辑，保存。
3. 等 1–3 分钟，线上已经更新。

就这样。想确认的话，打开 <https://longbatian.site> 看页面是不是新内容。

### B. 上传图片到 R2（电脑端专属）

手机传不了图，所以配图流程集中在这里。完整约定见 [[R2图床与图片上传说明]]，最简版：

1. 收集要用的图片（截图、PPT 导出的图、易学截图等）。
2. 上传到 R2 的 `img.longbatian.site`（两种方式）：
   - **跑脚本**：本地已有的上传脚本，一条命令传完一个目录；
   - **让 AI 传**：把图片和说明丢给电脑端的 AI（插件 ChatBox / Claude 等），让它调用上传脚本或工具传上去，并回给你直链。
3. 拿到直链，形如：

   ```markdown
   ![](https://img.longbatian.site/btwy/07-地支藏干-01.png)
   ```

4. **删除本地原图**（除非还要再编辑），保持库和仓库轻量。

### C. 批量整理（电脑才做得舒服）

- 统一 frontmatter、重排分类、合并/拆分文章、补索引页 —— 这些最好让 AI 先列改动清单再动手。
- 检查残留的本地图片引用、死链、缺 frontmatter，见下面「自检命令」。

## 写作规范速查

和手机端一致，详细版见 [[手机端更新维护说明]]：

- frontmatter：`title` / `description` / `date` / `tags` / `status`
- 文件名即 URL，定了别改名，避免 `:` `/` `#` 等字符
- 站内跳转用 `[[wikilink]]`，不用绝对 URL
- 图片一律用 R2 绝对直链，不塞本地附件

## 自检命令

在库根目录（或任意带 `rg` 的终端）跑：

```bash
# 1) 还有没有本地图片引用（应尽量为空）
rg -n '!\[\[.*\.(png|jpg|jpeg|gif|webp)' --glob '*.md'

# 2) 有没有指向旧图床的图片
rg -n 'raw\.gitcode\.com' --glob '*.md'

# 3) 缺少 title 的文件
rg --files-without-match '^title:' --glob '*.md'

# 4) 图床直链盘点
rg -o 'https://img\.longbatian\.site/[^) )]+' --glob '*.md' | sort -u | wc -l
```

（`Z-附件` 目录现在是空的，如果它又被塞满，说明有附件没走图床。）

## 可选：本地预览

想发布前先看一眼效果，需要电脑上有 Quartz 项目（不是必须，线上发布不依赖它）：

```bash
cd /path/to/quartz-showme
npx quartz build --serve   # 浏览器打开 http://localhost:8080
```

注意两点：

- 本地预览用的是项目里的 `content/`，和你的 Obsidian 库不是同一个目录，需要先手动同步一份过去再看。
- 服务器上用的是 `node quartz/bootstrap-cli.mjs build --concurrency=1`（低内存优化），本地不必照抄。

## 电脑端适合让 AI 做什么

| 场景 | 说明 |
|---|---|
| 图片批量上传 | 最省事：给目录 + 主题前缀，让它传完回直链列表 |
| 图片直链替换 | 把「待补图」占位逐个换成真实 R2 直链 |
| 结构重组 | 把零散笔记合并成体系，补分类入口页 |
| frontmatter 批量规范化 | 全库统一字段与标签 |
| 死链与重复检查 | 扫描 wikilink、同名文件、重复图片 |
| 站点内容审计 | 「哪些文章没配 description」「哪些标签只用过一次」 |

## 常见问题

### 我在电脑上改了，手机上看不到？

坚果云是双向同步的，通常几秒到几十秒。先看电脑端坚果云客户端是否显示已同步完成，再看手机端是否已拉取。

### 我能直接在电脑上改 `gh-pages` 或 `main` 的产物吗？

不能。`main` 的 `content/` 是服务器镜像，`gh-pages` 是构建产物，下一次发布都会覆盖。要改内容就改 Obsidian 库里的 Markdown。

### 需要我手动触发一次发布吗？

通常不需要。只有想跳过 5 分钟等待时，才登录服务器执行 `systemctl start nutstore-sync.service`（见 [[网站架构与发布管线]] 的常用命令）。

### 服务器 2027 年到期后怎么办？

网站本身在 GitHub Pages 上，不会下线；只是自动发布停止，届时需要本地手动构建发布，或者把管线迁到别处。预案见 [[网站架构与发布管线]] 的退役计划。
