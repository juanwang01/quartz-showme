# 一、电脑端 CMD - 编辑前：同步 GitHub 最新的 content 内容（复制即用）

cmd

```cmd
@echo off
chcp 65001 >nul
echo 📥 同步GitHub上content文件夹的最新内容...
cd /d E:\xiangmu\ShowMe\quartz
:: 仅拉取远程content文件夹的最新内容，不影响其他文件
git fetch origin main
git checkout origin/main -- content/
echo ✅ 同步完成！可编辑content文件夹内的笔记
pause
```

# 二、电脑端 CMD - 编辑后：上传 content 文件夹的修改到 GitHub（复制即用）

cmd

```cmd
@echo off
chcp 65001 >nul
echo 📤 上传content文件夹的修改到GitHub...
cd /d E:\xiangmu\ShowMe\quartz
:: 仅添加content文件夹的修改
git add content/
:: 检查是否有修改，有则提交推送
git diff --cached --quiet
if errorlevel 1 (
    git commit -m "电脑端同步笔记：%date% %time%"
    git push origin main
    echo ✅ 上传成功！服务器会自动同步最新内容
) else (
    echo ⚠️  未检测到content文件夹有修改，无需上传
)
pause
```

### 三、使用说明（极简两步）

#### 步骤 1：编辑笔记前

- 打开 CMD，复制「编辑前」的命令粘贴执行 → 同步手机 / 服务器推到 GitHub 的最新笔记；
- 然后打开 Obsidian 编辑`E:\xiangmu\ShowMe\quartz\content`里的内容。

#### 步骤 2：编辑笔记后

- 保存 Obsidian 的修改；
- 打开 CMD，复制「编辑后」的命令粘贴执行 → 仅把 content 的修改推到 GitHub，服务器会自动拉取更新。

### 四、核心优势（精准匹配你的需求）

1. **只处理 content 文件夹**：`git checkout origin/main -- content/` 仅同步 content，`git add content/` 仅提交 content，不改动项目其他配置文件；
2. **无强制覆盖风险**：相比`reset --hard`，仅操作 content 文件夹，避免误删电脑端的其他自定义配置；
3. **自动判断修改**：上传命令会先检查是否有修改，无修改则提示，避免空提交。

### 总结

1. **编辑前**：执行「同步命令」→ 拿到 GitHub 最新的 content 内容；
2. **编辑后**：执行「上传命令」→ 把修改的 content 推到 GitHub；
3. **核心逻辑**：全程只针对 content 文件夹，和手机端的操作逻辑完全一致，确保多端笔记同步不冲突。

执行时如果提示「git 不是内部命令」，只需把 Git 的安装路径（如`C:\Program Files\Git\bin`）添加到 Windows 环境变量的`Path`里即可。
