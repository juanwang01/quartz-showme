# 网站架构与发布管线

这份文档记录的是**现在真正在跑的那套系统**，以及它出问题时怎么查。

> 历史：2026-11-16 搭好并跑通（原文件《自动化发布管线搭建记录-2026-11-16》）；2026-11-22 图片迁到 R2 图床；2026-11-23 重写为现状文档。
> 服务器环境：Ubuntu 24.04，1.6G 内存，6G swap。

## 一句话目标

在手机上把 Markdown 放进坚果云，几分钟后网站自动更新。不需要登录服务器，不需要手动构建、推送、发布。

## 最终架构

```text
手机 / 电脑编辑 Obsidian 笔记
        │
        ▼
坚果云 WebDAV（唯一内容源）
        │ rclone bisync，systemd timer 每 5 分钟
        ▼
/srv/nutstore                      Obsidian 仓库本地镜像
        │ rsync --delete 单向镜像
        ▼
/srv/quartz-showme/content         Quartz 构建输入，提交到 main
        │ 提交 content → fetch/rebase → push main
        │ node quartz/bootstrap-cli.mjs build --concurrency=1
        ▼
/srv/quartz-showme/public          静态站点
        │ rsync 到 gh-pages worktree
        ▼
/srv/quartz-pages (gh-pages)       推送后 GitHub Pages 自动发布
        ▼
https://longbatian.site

旁路（不进同步链路）：
图片 ── 电脑端上传 ──▶ Cloudflare R2（img.longbatian.site）── CDN ──▶ 页面
```

## 职责边界

| 位置 | 谁负责 | 不负责 |
|---|---|---|
| 手机 Obsidian | 写作、改稿、插件内置 AI 整理文本 | 图片上传、git、构建、发布 |
| 电脑 Obsidian | 精修长文、**上传图片到 R2**、批量结构整理 | 手动 git push 内容、手动构建 |
| 坚果云 | 全平台同步，作为唯一内容源 | 构建、发布 |
| 服务器 | 同步检测、镜像、提交、构建、发布、告警 | 内容创作（`content/` 会被覆盖） |
| GitHub Pages | 托管静态产物、绑定自定义域名 | 构建（构建在服务器） |
| Cloudflare R2 | 存图片，CDN 分发 | 与站点构建无关，纯外链 |

## 关键原则

- **坚果云是唯一内容源**。项目的 `content/` 只是构建镜像，不要直接改；下一次同步会被覆盖。
- **删除也会传播**。删除坚果云文件后，`rsync --delete` 会删除 content 中的文件，git 记录删除，重新构建后线上页面消失。
- **元数据不发布**。`.obsidian/`、`.trash/`、`.claude/`、`.syncignore`、坚果云临时文件都会被排除；`.canvas` / `.excalidraw` 绘图现在会作为页面发布。
- **图片不进仓库**。图片统一走 R2 绝对直链，vault 里不留副本。
- **密钥不进入仓库**。SMTP 授权码、WebDAV 密码、SSH 私钥都只放在服务器本地，权限 600。
- **CDN 依赖本地化**。graph 的 D3/Pixi、KaTeX 的 CSS/JS/字体自托管在 `quartz/static/vendor`；构建前执行 `scripts/patch-quartz-cdn.mjs` 把插件里的 jsDelivr 地址换成本地路径，不要再改回 CDN。

## 发布流程

1. rclone bisync 把坚果云内容拉到 `/srv/nutstore`。
2. rsync 将 `/srv/nutstore` 镜像到 `content/`。
3. 有变化则提交并推送 main；若远端 main 有新的代码提交，钩子会先 fast-forward/rebase 拉取。
4. 若 main 的最新提交还没成功发布过，则构建 Quartz。
5. 构建产物同步到 gh-pages worktree，提交并推送。
6. GitHub Pages 自动更新站点。
7. 记录成功发布的 main 提交号；失败则下一轮重试。

实测耗时：同步约 22 秒，构建约 25–40 秒，发布 gh-pages 约 10–20 秒。加上 5 分钟定时窗口，从保存到线上通常 1–3 分钟，最坏 5 分半左右。

## 图片这条线不在管线里

图片完全绕过上面所有环节：

- 上传只在**电脑端**发生（脚本或让 AI 上传）。
- 笔记里写的是 `https://img.longbatian.site/...` 绝对直链，Quartz 原样输出。
- 因此**图片的可用性不受服务器影响**：服务器挂了，图片照常访问；图床挂了，页面文字照常。

## 故障处理

- rclone 同步失败：跳过构建，避免发布残缺内容，并发邮件告警。
- 同步锁 + 发布锁：防止两次同步或两次构建重叠。
- 磁盘低于 1.5GB：停止构建。
- content 之外出现已跟踪改动：停止并报错，不自动提交源码。
- 本地与远端 main 分叉：自动 rebase；冲突则中止并告警。
- 构建失败：不更新部署标记，下一轮重试；同一提交 15 分钟内只重试一次。
- 插件依赖：拉取代码后钩子会再检查依赖并自动 `npm ci`；构建使用 `CI=1`，插件加载失败会直接中止，不再发布残缺站点。
- 构建日志显示依赖缺失：自动 `npm ci` 后重试一次。
- 产物检查：必须有 `index.html`，文件数不少于 50。
- gh-pages 推送失败：自动重试一次；仍失败则保留旧站点。
- 清理残留 `.git/index.lock`，恢复被失败构建删掉的 `public/CNAME`。
- 日志按天轮转，保留 14 天。

## 邮件告警

重大错误会发送到邮箱，同类错误 6 小时内只发一封，失败后首次成功发布会发送「发布已恢复」。

覆盖范围：rclone 失败、磁盘不足、镜像失败、git 操作失败、依赖安装失败、构建失败、产物异常、gh-pages 失败、脚本异常退出。

## 常见问题

### 首页为什么没有自动出现新文章？

首页 `content/index.md` 是手工策展的门户，「最近更新」也是手写列表。新文章会生成独立页面，并进入搜索索引、文件树和 sitemap，但不会自动插进首页正文。若希望自动展示，可以在 Quartz 布局中增加「最近发布」组件，或继续手工维护首页链接。

### 频繁同步会不会重复构建？

- 同一个 5 分钟窗口内的多次改动会合并成一次同步、一次构建。
- 跨窗口的改动会各构建一次；单次构建约 35 秒，锁和 systemd 会防止重叠，不会损坏站点。
- 如果改动频繁，可以先批量改完再等同步；也可以把定时器间隔调大。
- 需要立即发布时，执行 `systemctl start nutstore-sync.service`，它会先同步再构建。

### 直接在服务器上写 content 会触发发布吗？

- 写 `/srv/nutstore`：下一次 bisync 会检测到并上传坚果云，然后触发钩子，最迟 5 分钟。
- 直接写项目的 `content/`：会被下一次镜像覆盖，不要这样做。
- 想马上发布：写 `/srv/nutstore` 后手动执行 `systemctl start nutstore-sync.service`。

### 删除文章后线上会消失吗？

会。删除坚果云里的文件，下一次同步会删除 content 中的对应文件，git 提交删除，重新构建后线上页面消失。

### 手机端能做什么、不能做什么？

能：写、改、用插件内置 AI 整理笔记（详见 [[手机端更新维护说明]]）。
不能：上传图片、跑 git、触发发布、看服务器日志。

## 常用命令

```bash
# 查看状态
systemctl list-timers nutstore-sync.timer
systemctl status nutstore-sync.service

# 立即同步并发布
systemctl start nutstore-sync.service

# 只跑发布钩子
/usr/local/bin/nutstore-post-sync.sh 0

# 日志
tail -f /var/log/nutstore-sync.log
tail -f /var/log/nutstore-deploy.log
tail -f /var/log/nutstore-mail.log

# 暂停 / 恢复自动发布
systemctl stop nutstore-sync.timer
systemctl start nutstore-sync.timer
```

## 服务器退役计划

这台服务器只会使用到 **2027-09-12 23:00**，之后不续费。

需要明确的是：

- **GitHub Pages 上的网站不依赖这台服务器**，服务器到期后网站继续在线。
- **图片在 Cloudflare R2 上**，也不依赖服务器。
- **坚果云里的内容也不依赖服务器**，笔记仍然保留。
- 到期后只是**自动同步和自动发布停止**。

退役前建议按顺序操作：

1. 确认所有内容已同步到坚果云，线上站点是最新版本。
2. 停止自动任务：

   ```bash
   systemctl disable --now nutstore-sync.timer
   systemctl disable --now nutstore-sync.service
   ```

3. 撤销凭据：
   - 坚果云：账户信息 → 安全选项 → 第三方应用管理，删除 rclone 使用的应用密码。
   - GitHub：仓库 Settings → Deploy keys，删除服务器上的公钥。
   - 邮箱：如果不再需要 SMTP 告警，撤销授权码。
4. 删除本地敏感配置：`/etc/nutstore-mail.conf`、`/root/.ssh` 中对应的部署密钥。
5. 在服务商到期前释放服务器。

到期后若仍想自动发布，可选路线：

- 本地手动构建并推 `gh-pages`（最省事，但需要电脑开着）；
- 同一套管线迁到另一台机器（脚本都是现成的，改路径即可）；
- 改成 GitHub Actions + 坚果云同步的纯云端方案（需要把内容导出到仓库）。

## 安全提醒

- `/etc/nutstore-mail.conf` 权限必须是 600。
- 不在 Git 仓库中保存任何密码、授权码或私钥。
- 定期检查和撤销不再使用的应用密码与部署密钥。
- 邮件告警只发送错误摘要和最近日志，不发送密钥。
