手机端 Termux 笔记同步脚本更新维护说明
 
一、脚本功能与文件清单
 
脚本文件 功能 使用时机 
 pull_content.sh  拉取 GitHub 最新 content 目录、锁定核心版本  14d264c  编辑笔记前，确保本地笔记是最新版本 
 push_content.sh  提交 content 目录修改、推送到 GitHub 编辑笔记后，同步本地修改到远程仓库 
 
二、核心操作命令（极简流程）
 
1. 前置准备（每次打开 Termux 必做）
 
bash
  

# 1. 授予存储权限（首次使用需执行，后续可跳过）
termux-setup-storage

# 2. 进入仓库目录（核心！所有操作必须在此目录下执行）
cd /storage/emulated/0/Documents/quartz-showme
 
 
2. 编辑笔记前：同步最新内容
 
bash
  

# 运行同步脚本
bash pull_content.sh

# 脚本正常输出示例
# [2025-xx-xx xx:xx:xx] 拉取远程最新代码...
# [2025-xx-xx xx:xx:xx] 锁定核心版本为14d264c...
# [2025-xx-xx xx:xx:xx] 同步content目录...
# [2025-xx-xx xx:xx:xx] ✅ 手机端同步完成！可编辑笔记
 
 
3. 编辑笔记后：提交推送修改
 
bash
  

# 运行提交脚本
bash push_content.sh

# 脚本正常输出示例（有修改时）
# [2025-xx-xx xx:xx:xx] 添加content目录修改...
# [2025-xx-xx xx:xx:xx] 提交修改：手机端同步笔记：2025-xx-xx xx:xx:xx
# [2025-xx-xx xx:xx:xx] 推送到GitHub...
# [2025-xx-xx xx:xx:xx] ✅ 笔记提交完成！

# 无修改时输出
# [2025-xx-xx xx:xx:xx] 添加content目录修改...
# [2025-xx-xx xx:xx:xx] ⚠️  无笔记修改，无需提交
 
 
三、脚本有效性测试命令
 
1. 测试脚本是否能识别修改
 
bash
  

# 1. 先在 content 目录新建一个测试文件
touch content/test_note.md

# 2. 运行提交脚本，查看是否能检测到新文件
bash push_content.sh

# 3. 测试完成后，可删除测试文件（可选）
rm content/test_note.md
 
 
2. 验证推送是否成功（GitHub 端）
 
bash
  

# 查看本地分支与远程分支是否一致
git status

# 正常输出：Your branch is up to date with 'origin/main'
 
 
3. 检查 SSH 连接稳定性（解决推送失败）
 
bash
  

# 1. 测试 443 端口 SSH 连接
ssh -T git@github.com

# 成功提示：Hi juanwang01! You've successfully authenticated...

# 2. 若连接失败，重新配置 SSH 443 端口
nano ~/.ssh/config
# 粘贴以下内容并保存
Host github.com
  Hostname ssh.github.com
  Port 443
  User git
  IdentityFile ~/.ssh/id_rsa

# 3. 修复配置文件权限
chmod 700 ~/.ssh
chmod 600 ~/.ssh/config
chmod 600 ~/.ssh/id_rsa
 
 
四、常见问题维护方案
 
问题现象 原因 解决命令 
脚本提示  Permission denied  手机存储目录无法设置执行权限 用  bash 脚本名.sh  运行，不要用  ./脚本名.sh  
推送时提示用户名密码 远程地址是 HTTPS 或 SSH 配置失效  git remote set-url origin git@github.com:juanwang01/quartz-showme.git  
 Connection closed by xxx port 22  22 端口被网络拦截 配置 443 端口 SSH 连接（见上文） 
脚本检测不到修改 新文件未被 Git 追踪或路径有中文 手动执行  git add content/  后再运行脚本；尽量用英文文件名
