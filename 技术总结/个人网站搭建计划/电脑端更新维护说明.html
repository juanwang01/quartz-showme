电脑端更新维护说明

一句话

电脑端只做手机做不了的两件事：精修长文 和 把图片传上 R2 图床。同步与发布仍然全自动。

工作目录变了

老流程（已废弃）现在
写作目录E:\xiangmu\ShowMe\quartz\content坚果云同步的 Obsidian 库（和手机同一份）
同步方式CMD 脚本 git checkout origin/main -- content/、git add content/、git push坚果云客户端自动同步
发布方式推 main 后等服务器拉取构建服务器检测到坚果云变化后自动构建并推 gh-pages

不要再在 quartz 项目里写笔记。 项目里的 content/ 只是构建镜像，服务器每次同步都会用 rsync --delete 覆盖它，本地写进去的东西迟早消失。

也不要再执行老的两段 CMD 脚本。 现在手动往 main 推 content，下一轮镜像会把它覆盖；运气不好还会和服务器推送撞成 rebase 冲突，触发告警邮件。

日常流程

A. 写 / 改文章

  1. 打开 Obsidian（库 = 坚果云同步目录）。
  2. 正常编辑，保存。
  3. 等 1–3 分钟，线上已经更新。

就这样。想确认的话，打开 https://longbatian.site 看页面是不是新内容。

B. 上传图片到 R2（电脑端专属）

手机传不了图，所以配图流程集中在这里。完整约定见 R2图床与图片上传说明，最简版：

  1. 收集要用的图片（截图、PPT 导出的图、易学截图等）。

  2. 上传到 R2 的 img.longbatian.site（两种方式）：

    • 跑脚本：本地已有的上传脚本，一条命令传完一个目录；
    • 让 AI 传：把图片和说明丢给电脑端的 AI（插件 ChatBox / Claude 等），让它调用上传脚本或工具传上去，并回给你直链。

写作规范速查

和手机端一致，详细版见 手机端更新维护说明：

  • frontmatter：title / description / date / tags / status
  • 文件名即 URL，定了别改名，避免 : / # 等字符
  • 站内跳转用 [[wikilink]]，不用绝对 URL
  • 图片一律用 R2 绝对直链，不塞本地附件

电脑端适合让 AI 做什么

场景说明
图片批量上传最省事：给目录 + 主题前缀，让它传完回直链列表
图片直链替换把「待补图」占位逐个换成真实 R2 直链
结构重组把零散笔记合并成体系，补分类入口页
frontmatter 批量规范化全库统一字段与标签
死链与重复检查扫描 wikilink、同名文件、重复图片
站点内容审计「哪些文章没配 description」「哪些标签只用过一次」

常见问题

我在电脑上改了，手机上看不到？

坚果云是双向同步的，通常几秒到几十秒。先看电脑端坚果云客户端是否显示已同步完成，再看手机端是否已拉取。

我能直接在电脑上改 gh-pages 或 main 的产物吗？

不能。main 的 content/ 是服务器镜像，gh-pages 是构建产物，下一次发布都会覆盖。要改内容就改 Obsidian 库里的 Markdown。

需要我手动触发一次发布吗？

通常不需要。只有想跳过 5 分钟等待时，才登录服务器执行 systemctl start nutstore-sync.service（见 网站架构与发布管线 的常用命令）。

服务器 2027 年到期后怎么办？

网站本身在 GitHub Pages 上，不会下线；只是自动发布停止，届时需要本地手动构建发布，或者把管线迁到别处。预案见 网站架构与发布管线 的退役计划。

检查清单

  • 编辑的是坚果云库里的 Markdown，不是 quartz/content
  • 没有执行老的 git 同步脚本
  • 新图已上传 R2，笔记里用的是 https://img.longbatian.site/...
  • 本地图片副本已删除
  • frontmatter 完整、文件名未随意改动
